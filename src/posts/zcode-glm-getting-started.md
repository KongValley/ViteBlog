最近把 [ZCode](https://github.com) + GLM 这套组合用进了日常开发，体验下来最大的感受是：写代码的重心从"一行行敲"变成了"把需求说清楚，再把关实现"。这个系列的文章就记录一下这套工作流。

## ZCode 和 GLM 分别是什么

两者的分工很清晰：

- **ZCode** 是一个跑在终端里的交互式 AI 编程代理。它能读写项目文件、执行 shell 命令、跑构建和测试、操作 git，你用自然语言提需求，它来动手实现。
- **GLM** 是智谱的大模型，是 ZCode 背后的"大脑"。通过 GLM 的编码套餐接入后，日常的读代码、写功能、修 bug 都够用。

换句话说：ZCode 负责手和眼，GLM 负责脑。

## 上手三步

1. 按官方指引安装 ZCode CLI，在项目根目录启动；
2. 配置 GLM 的 API Key（智谱的编码套餐），选好模型；
3. 直接用中文提需求，比如：

```text
给文章卡片加一个按文章随机显示的像素图标
```

它会先自己读代码搞清楚结构，再给出改哪些文件的计划，确认后动手实现，最后跑一遍构建验证。

## 第一次使用的几点感受

- **它会先看代码再动手**。我第一句话只说了需求，没说改哪个文件，它自己把组件、数据、样式都翻了一遍才提方案，这点比想象中省心。
- **每一步都可见**。改哪个文件、执行什么命令都会列出来，涉及删改还会先跟你确认。
- **中文沟通完全没问题**。描述bug、讨论方案都可以用中文，它甚至会用中文写提交信息。
