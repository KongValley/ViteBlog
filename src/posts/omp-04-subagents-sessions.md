系列收尾。上一篇讲了[扩展面](/post/omp-03-context-skills-mcp)，这篇讲两件"规模"上的事：一个会话怎么拆成多个代理并行，以及长任务怎么管理会话。

## 子代理：一个任务拆给多个分身

代理干活时会自己调 task 工具开子代理，你也可以直接说"并行查这两块"。内置几个角色：

- **scout**：只读侦查，查代码、找模式，不动文件；
- **task**：通用干将，能改能跑；
- **reviewer** / **security-reviewer**：评审与安全审查，结论给证据；
- **sonic**：低推理档，纯机械活（批量替换、收集数据）。

关键语义：

- **子代理不带父对话历史**，拿到的是任务书 + 共享上下文，所以任务描述要自包含；
- **结果按结构化对象回收**，父代理直接读字段，不用从散文里扒；
- 并发有上限，超出的排队；`task.isolation` 打开后每个子代理在独立工作区（worktree）里改，最后以补丁或分支合并，兄弟之间不打架。

`Alt+A` 打开 Agent Hub 能实时看每个分身在干嘛：读它的转录、插一句话纠偏、parked 的唤醒、卡死的直接杀掉，不用动主会话。`/jobs` 看后台任务列表。子代理的产物用 `agent://<id>` 读，过程转录在 `history://<id>`；要跟进就给已有的分身发消息——它带着上下文，比新开一个省。

一个实用场景：`/review` 会并行开评审子代理，扫分支、单次提交或未提交改动，每个问题标 P0–P3 优先级和置信度，最后给"能不能发布"的结论——比自己逐行读 diff 快得多。

## 会话：可续、可分叉、可分享

会话落盘在 `~/.omp/agent/sessions/<目录编码>/` 下的 JSONL 文件，追加式写入；分支只是移动指针，不改历史。

```bash
omp --continue        # 接着最近一次
omp --resume          # 弹出选择器
omp --resume <id>     # 直接恢复指定会话
omp --fork <id>       # 从某会话分叉出新会话
```

会话内几个"清空"命令，差别微妙但重要：

| 命令 | 干什么 | 什么还在 |
| --- | --- | --- |
| `/new` | 开全新会话 | 旧的还在磁盘上 |
| `/clear` | 就地清空对话上下文 | 磁盘历史完整保留 |
| `/fresh` | 只重置模型侧的流状态 | 你能看到的对话一字不丢 |
| `/delete` | 删掉当前持久化会话再开新的 | 没了 |

`/fresh` 是救命的：模型流卡死、提示缓存漂移时，不丢对话只换"管道"。

产出与分享：

- `/export` 导出成 HTML（子代理转录也嵌进去）；
- `/share` 生成端到端加密的分享链接，密钥只在 URL 片段里，服务器看不到；
- `/collab` 把当前会话挂上中继，队友 `omp join` 或开浏览器实时围观；只读模式连方向盘都不给。
