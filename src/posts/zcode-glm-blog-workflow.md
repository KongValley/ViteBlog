上一篇聊了上手，这篇拆实战。你现在看到的这个博客，最近一堆迭代就是用 ZCode + GLM 做的：首页的文章图标池、列表分页、右下角的回到顶部按钮，全是这样一笔一笔"说"出来的。

## 一个完整的工作循环

以"加回到顶部按钮"为例，整个过程大概是这样：

```text
我：页面右下能不能加个回到顶部的按钮
AI：可以。（先自己读了 App.tsx 和 style.css，确认路由结构和现有样式语言）
AI：新建全局组件 BackToTop，滚动超过 320px 才出现，样式复用标签按钮的边框和投影
我：可以
AI：写组件 → 挂载 → 加样式 → 跑构建 → 起本地服务用浏览器实测：
    首屏无按钮、滚动后出现、点击后回到顶部并隐藏 → 全部通过
AI：提交了 commit，要不要推送？
```

我全程只说了两句话，剩下的它自己完成。最后它在浏览器里把三种状态都截图验证过，这个"自己验证"的环节比我预想的可靠。

## 它处理过的那些活儿

这段时间让它干过的活，按类型分大概有：

- **像素画**：首页文章卡片的图标是一组 12×12 的像素精灵。我说"要个游戏手柄"，它画完还会自己渲染到 18px、24px 对比哪个能认出来，上一版"缩成一团蓝"就是它自己发现重绘的；
- **功能开发**：分页功能，包括页码同步到 URL（`?page=2`，刷新不丢）、切换标签自动回第一页、翻页滚回顶部；
- **排查问题**：图标显示成"NaN 日"这种小毛病，它能顺着代码找到原因并给出几种修法。

## 几个让我印象深的细节

**它会用真实环境验证。** 分页做完后，它起了本地服务，用浏览器自动化点了一遍"下一页"，检查文章数量、URL、按钮禁用状态，还测了标签筛选后页码是否重置——比我自己手点还全。

**它对旧代码是尊重的。** 加分页时它先去读了现有的标签按钮样式，让新分页条复用同一套 3px 边框加像素投影，所以新功能长出来不违和。

**网络抽风它自己兜底。** 有次推送到 GitHub 连接被重置，它会等几十秒自动换 HTTP/1.1 重试，成功后老老实实报告"重试后成功"，没有假装一次过。
